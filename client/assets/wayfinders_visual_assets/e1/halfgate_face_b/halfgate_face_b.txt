Halfgate face B -- iso lozenge patches (E1 POC) -- v6 (transform=none)
=======================================================================

Source: Owner's Inbox/Media/E1/sources/halfgate-zone-iso-1024x512.png
  (1024x512 RGBA -- Didier's hand-projected iso lozenge, GIMP)

Pipeline (v6 -- locked 2026-05-13):
  transform = none
    No warp. No rotation. No resampling.
    The source is ALREADY projected in iso (Didier did it in GIMP).
    This script only slices the source into 16 sub-lozenges 256x128
    and applies a pixel-perfect iso alpha mask to each.

  source = halfgate-zone-iso-1024x512.png (Didier GIMP)

Iso grid topology (UNCHANGED from v3/v5):
  For cell (gx, gy) in [0..3] x [0..3]:
      top_apex_x = 512 + (gx - gy) * 128
      top_apex_y =       (gx + gy) *  64
      bbox       = (top_x - 128, top_y, top_x + 128, top_y + 128)
      iso mask:    apply_iso_mask(width=256)  -- pixel-perfect

Top apex coords (UNCHANGED):
  (0,0)=(512,  0)  (1,0)=(640, 64)  (2,0)=(768,128)  (3,0)=(896,192)
  (0,1)=(384, 64)  (1,1)=(512,128)  (2,1)=(640,192)  (3,1)=(768,256)
  (0,2)=(256,128)  (1,2)=(384,192)  (2,2)=(512,256)  (3,2)=(640,320)
  (0,3)=(128,192)  (1,3)=(256,256)  (2,3)=(384,320)  (3,3)=(512,384)

File naming (UNCHANGED v3/v5 identity mapping):
  halfgate_face_b_<gx><gy>.png

Why v6 vs v5:
  v5 ran a PIL PERSPECTIVE warp from a 1024x1024 top-down source to the
  1024x512 iso canvas. The warp introduced bicubic blur + visible AI-smell
  in the lozenge content (especially at the apex regions where the source
  was stretched the most). v6 sidesteps the warp entirely by using
  Didier's GIMP-projected source AS-IS -- pixel content is preserved
  byte-for-byte inside the union of the 16 sub-lozenges.

Diagnostic guarantee (v6):
  Remount the 16 sub-lozenges back onto a 1024x512 canvas. Compare RGB
  against the source inside the union of the 16 iso masks.
  Expected: 0 differing pixels. Anything else = pavage bug.
